01 / Get the question right

Three questions.
Separate outputs.

The trained model identifies subtype. Nodal involvement describes spread at surgery. Recurrence describes a later event. Each task has its own labels and tests.

Trained and runnable

Subtype classification

“Which of these two cancer subtypes matches this known tumour?”

Adenocarcinoma (AC) and squamous cell carcinoma (SCC) are the two labels in the trained task. The model learns from tumour measurements and known diagnoses.

→It needs a known tumour region or compatible extracted features. It does not find an unknown tumour in a full CT scan.
Training gate closed

Lymph-node involvement

“How likely is cancer in the lymph nodes at surgery?”

Use a matching preoperative CT to estimate N0 versus N1/N2/N3. Pathology supplies the target, never an input.

!The source contains nodal labels. Scan timing still needs verification before fitting.
Training gate closed

Recurrence prediction

“What is the chance of a first recurrence within two years after surgery?”

This requires a verified surgery date, recurrence assessment and follow-up. Death before recurrence must be counted as a separate possible first event.

!No recurrence model has been trained on the current clinical data. The guide shows its protocol and audit, not predicted risks.
No unknown-tumour detectionNo automated tumour segmentationNo treatment recommendationNo trained benign-versus-malignant model

What is data leakage, in engineering terms?

It is like using the exam answers while preparing for the exam. A reported score becomes too optimistic when evaluation information affects learning.

Keep patients apartRows from the same patient must not cross training and evaluation boundaries.
Fit transforms inside trainingFill values, scaling and feature selection must use each training fold only.
Keep future outcomes outDiagnosis labels and future recurrence or survival information must not become model inputs.

Accuracy: how many were correct?

31 correct predictions ÷ 35 test patients = 88.6%. Always predicting AC already gets 28/35 correct, or 80.0%.

Balanced accuracy: are both classes served?

It gives equal weight to AC recall and SCC recall. For the default: average of 96.4% and 57.1% = 76.8%.

AUC: how well does the score rank cases?

AUC tests ranking across thresholds. The default’s test AUC is 0.852. It is not an 85.2% accuracy claim.

!The default’s nested development accuracy is 80.8%. Its 88.6% test accuracy is a different metric on different patients. The paper’s 83% used another cohort and is not a direct comparison.
Why does the 91.4% candidate remain experimental?

The bagged model combines 12 logistic pipelines and averages their probabilities. It gets one more AC case right on these test patients. SCC recall remains 4/7.

Both models score 80.8% nested development accuracy. The default has higher development balanced accuracy: 55.9% versus 52.4%. The frozen selection therefore keeps the default.

All these results reuse previously inspected patients. New independent patients are required before a general performance claim.

Where do the paper baseline and other models fit?

The project starts from a published neural-network approach. Its paper-style baseline is implemented alongside alternative models. The main accuracy experiment compares 12 variants, including logistic regression, support vector machines and tree-based models.

On these same 35 test patients, the accuracy-selected paper-style neural network scores 71.4% accuracy and 50.0% balanced accuracy. These local results do not reproduce the paper's original cohort.

Separate experiments test clinical inputs, imaging-plus-clinical inputs, pretrained image features and a pretrained tabular model. Each experiment has its own input requirements and report. Their scores must not be pooled as if they came from one test.

A more complex model is a hypothesis to test. The default remains the radiomics-only logistic model selected through development evidence.

What exactly triggers the dashboard’s review flag?

The selected-class probability is below 70%, or the SCC probability is less than 10 percentage points from the saved threshold. The code uses strict “less than” comparisons.

This is an experimental flag for inspecting an output. It is not a validated clinical triage rule. Feature contributions for an individual case are not inferred from these probabilities.

07 / Recurrence after surgery

A trained classifier.
A separate time-based study.

The dashboard now predicts source-recorded recurrence. A one-year or two-year estimate still requires verified event timing and recurrence assessment.

Trained exploratory classifier · 12 October 2026

Run a real recurrence prediction

Open the dashboard’s Recurrence tab. Choose an example patient, enter a postoperative profile, or upload compatible features. The clinical model uses age, sex, smoking, pathological T/N categories, tumour grade and invasion findings. A second model adds CT radiomics. Both produce actual probabilities, explanations, input checks and downloadable reports.

Measured default results: 104 development patients and 35 test patients; 48.6% accuracy, 58.0% balanced accuracy and AUC 0.592. The model finds 8/10 recorded recurrences and produces 16 false alarms. The always-no reference achieves 71.4% accuracy with zero recurrence recall. These scores are exploratory and separate from subtype accuracy.

What the score means: recurrence recorded during the source study’s varying follow-up. There is no fixed time horizon. A source “no” does not prove future freedom from recurrence. The saved 22% threshold comes from development predictions, so a score below 50% can still produce a positive classification.

This weak classifier requires surgical pathology, is not independently validated, and does not establish a new research method. Read artifacts/recurrence_recorded/report.json and docs/RUNBOOK.md. The audit below concerns the separate time-based model, which remains locked.

Two unresolved definitions

1. Which CT and surgery date?
The scan-to-surgery interval and its match to the published radiomic scan need independent source verification.

2. What does the follow-up date mean?
“Last known alive” does not establish that the patient was assessed for recurrence through that date.

!Training is blocked until both definitions have documented evidence, or suitable replacement follow-up data are obtained.

The planned models compare age and tumour volume with an added radiomics summary. Separate recurrence and death models combine into a recurrence probability over time.

How will time-based recurrence performance be evaluated?

The primary score is a censoring-adjusted probability-error score, called the IPCW Brier score, at 730 days. Lower is better. Ranking and calibration provide additional checks.

Evaluation accounts for unknown outcomes after early censoring and death before recurrence. The code suppresses horizons with insufficient training support. No categorical “high risk” threshold or follow-up schedule is defined.

Planned time-based outputs are recurrence probability, competing-death probability and event-free probability at supported horizons. Together they sum to one. The time-based model remains untrained. The separate recorded-recurrence classifier above is trained and has no time horizon.

All six additions, in plain language

CT workbench: inspect CT geometry, mask alignment, slice views and physical boundary coordinates.

Mask stability: remeasure the original, 1 mm eroded and 1 mm dilated tumour regions. Export the actual features and volume changes.

Case explanation: the default logistic model exposes exact contributions to its transformed log-odds score. These describe the fitted calculation, not a biological cause.

Input review: compare values with reference ranges from fitted training patients only. Missing inputs or more than 10% outside the ranges trigger review.

Research reports: save probabilities, input checks, explanation, timestamp and model/input hashes in printable HTML with an embedded JSON record.

API and evaluation: expose registered models through a local HTTP interface. A separate validation command scores a compatible new cohort without refitting or changing the threshold.

Choose an answer.

Segmentation mask

A labelled 3D region that marks the known tumour. Alignment, boundary choice and voxel spacing affect its measurements.

Log odds and contributions

The default model adds an intercept and weighted transformed inputs. This score is called log odds. Converting the total gives an SCC probability. Contributions use score units, not percentage points.

Training reference range

The 1st–99th percentile interval of a feature in fitted training patients. An unusual value can trigger input review. It does not establish that a prediction is wrong.

SHA-256 hash

A file or input fingerprint. The report records it so a team can identify the exact model and input used. A matching hash does not establish clinical validity.

Radiomics

Measurements of tumour shape, intensity and spatial texture extracted from an image region. They become numerical model inputs.

Inference

Running the saved model on a case. Its preprocessing and model settings remain fixed.

Cross-validation

Repeated learning and checking within development patients. It estimates development performance and helps choose settings.

Recall

The fraction of cases in one actual class that the model classifies correctly. SCC recall is 4/7 on the default’s test set.

Calibration

How well predicted probabilities agree with observed outcome frequencies in suitable evaluation data. A confident score alone does not establish calibration.

Right censoring

Observation stops before the event or requested horizon. The later outcome is unknown.

Competing event

An event that prevents the target event from occurring later. For first recurrence, death before recurrence is the competing event.

Provenance

The source and transformation history of the data, features and models. It helps reproduce and audit a result.
